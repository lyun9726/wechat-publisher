# 图片制作

## 选择顺序

产品、模型、教程和行业文章按下面顺序选图。

1. 用户提供的真实截图。
2. 官方产品页、官方文档和官方演示截图。
3. 基于真实素材重新排版的封面。
4. 真实截图无法表达关系时制作的信息图。
5. 用户明确需要插画、概念图或创意封面时使用 AI 生图。

不得生成看起来像官方产品界面的假截图，也不得用模型生成的“测试结果”冒充实际运行。

## 截图

- 保留能证明正文判断的区域，包括产品名、关键控件、结果或版本信息。
- 裁掉账号、邮件、API key、无关标签页、浏览记录和大块空白。
- 正文图按手机宽度检查，关键文字不能依靠放大才能阅读。
- 截图来源和拍摄日期记录在 `image-plan.md` 或 `sources.md`。

## 封面

- 推荐 900×383，比例约 2.35:1。
- 标题尽量压缩成两行，手机缩略图里仍能辨认。
- 产品稿可用官方素材重新排版，但不要擅自重画官方 Logo。
- 用户只要首图时，只交付 `images/00-cover.*`，不要机械增加正文图。
- 默认把封面作为正文最后一张图，不在开头重复展示。用户在公众号后台通过“从正文选择”设为封面后，可以直接删除文末图片。
- 默认封面必须有可读标题或核心短语。只把一张横向截图裁成 900×383 不算完成，除非用户明确要无字封面。

有官方截图但没有设计工具时，可以运行：

```bash
python3 scripts/build_cover.py images/source.png \
  --headline "封面主标题" \
  --eyebrow "栏目或产品名" \
  --subtitle "一句补充信息" \
  --output images/00-cover.png
```

脚本用真实图片做背景，添加深色遮罩和可读文字。目标环境没有 Chrome 时会保留可截图的 HTML，Agent 应使用可用浏览器按 900×383 截图。

## 文件与引用

- 正文图按出现顺序命名，封面固定为 `00-cover`，文件名不决定它在正文中的位置。
- `article.md` 使用相对路径，例如 `images/01-console.png`。
- 每张图写有意义的替代文字。
- 图片编辑保留可追溯的原始素材或制作脚本，不覆盖用户原文件。
- GIF 可以保留动图，但要检查文件体积和公众号兼容性；无法保证时同时保留一张代表性静帧。
- 截图中的账号、邮件、订单、API key、Cookie、私密文件名和无关浏览记录必须裁掉或遮挡。
