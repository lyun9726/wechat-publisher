# 写作与事实

## 材料先于篇幅

现实文章超过 1200 个汉字时，动笔前至少列出五件具体材料。材料可以是官方功能、版本限制、时间、数字、真实操作、用户原话或可核验案例。五个抽象观点不算五件材料。

公开资料能补足就先研究。产品、模型、价格、政策、人物身份和热点消息都可能变化，应在写作当日重新确认。优先使用官方文档、论文、正式公告和项目仓库；媒体用于补背景，不能替代关键一手来源。

## 不替作者编经历

用户说“看见”不能扩成“亲测”。用户提供一张截图，不能补出注册、付款、运行成功和结果。没有来源的精确耗时、收益、客户案例、对话和现场细节不能写成事实。

可以把公开材料写成资料解读、教程或测试计划。尚未实际跑通的步骤要说明需要什么条件，不能写“亲测成功”。

## 公众号正文

- 开头尽快碰到一件具体事情或读者正在卡住的问题。
- 小标题用于定位，不要求每段都设置。
- 每个新段落增加事实、动作、区别、限制或结果。
- 一段抽象解释后尽快回到一次操作、一个数字或一项真实限制。
- 普通中文先写人和动作，再补原因与条件。
- 不用机构汇报腔、商业黑话和固定反转句式抬高普通事实。
- 结尾回到读者下一步能做的事，不重复全文。

## 成稿语言硬检查

正文、标题、小标题和图片说明都执行下面的规则。引用原文命中时改成转述，网址和代码不受影响。

- 不使用中文冒号和英文冒号引出解释、总结、列表或步骤。冒号只保留在人物直接说出的原话里。
- 不使用 `—`、`——` 或 `–`。
- 不写固定翻案句，包括“不是……而是……”“并非……而是……”“不在于……而在于……”“你以为……其实……”“看似……实则……”。直接说判断和依据。
- 不用“先说结论”“说到底”“真正的问题”“本质上”“值得注意的是”充当洞察路标。
- 同构排比最多两项。第三项改成普通句子，或补入事实后重新组织。
- 新段落必须增加事实、动作、限制、步骤或结果，不能只换一种说法重复上一段。

初稿完成后运行：

```bash
python3 scripts/check_style.py runs/<slug>/article.md
```

检查失败时先修改，再进入配图与 HTML 阶段。脚本只负责拦截明确模式，人工仍要检查重复、虚假细节和段落推进。

## 标题与摘要

标题只能写到事实允许的位置。内测不能写成全面开放，演示不能写成生产可用，教程预估不能写成已经亲测的精确耗时。

先拟三到五个候选标题，再检查每个标题的主体、动作、数字、范围和时间是否都有来源。标题优先交付一个清楚的变化和一个具体收益。数字有效时保留数字；没有可靠数字就不用“爆火”“全网第一”“干掉”“免费无限”等词硬抬点击率。

标题可以有情绪，但正文必须兑现标题承诺。动态排名要带范围，免费要写清额度与期限，开源要核对许可证，实测要确实运行并留下产物。

摘要单独保存在 `article.md` 开头的引用块中。导入 Raphael 时移除摘要与 H1，公众号后台分别填写标题和摘要。

## 利云文章的默认落点

使用 `author-profile.liyun.json` 时，开头和结尾按配置原样放入。正文要回答普通读者接下来能做什么，产品发布稿至少给出适用人群、使用入口、限制和一项可以照着尝试的任务。项目介绍稿至少给出安装条件、能解决的问题、真实示例和安全边界。

不要为了保持固定篇幅重复解释。材料只能支撑 1500 字就写 1500 字。用户明确要“保姆级教程”时，步骤必须来自官方文档或真实操作，不能靠合理猜测补齐。

## 来源

完全依赖公开材料的稿件，在文末列出少量关键来源。链接要直接支持正文判断，不用搜索结果页。涉及当前产品或软件的教程，优先链接官方文档和官方仓库。

目标环境安装了 `human-writing` 时可以用它完成初稿和修订。没有该 Skill 时仍要遵守本文件的材料、事实和语言边界，不能把缺少依赖当成编造细节的理由。
