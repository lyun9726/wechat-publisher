# 工作流与完成条件

## 一次完整制作

1. 读取作者配置和当轮要求，确定交付深度。
2. 建立文章包，记录目标读者、标题承诺、事实边界和交付指纹。
3. 搜集一手材料。长现实稿至少五件具体材料，动态信息注明核验日期。
4. 拟三到五个标题，逐个检查是否有事实支撑，再选一个最清楚、最有读者收益的标题。
5. 写正文并复核。文章每个主要段落都要增加事实、步骤、区别、限制或结果。运行 `check_style.py` 清理硬性写作痕迹。
6. 需要图片时先写图片计划，再截图、裁图和做带可读标题的封面。产品稿不用虚假 AI 界面图，普通横向截图不能直接当默认封面。
7. 校验文章包。封面按默认配置放在全文最后。
8. 需要直接复制时生成独立 HTML，把图片内嵌为 data URL，再检查图片数量、正文指纹和本地路径。
9. 用浏览器打开 HTML，检查桌面和窄屏预览。点击复制按钮后，目标是把正文富文本粘贴进公众号，不是复制整个网页。
10. 按授权停在文件交付、公众号草稿或正式发布。保存草稿不等于发布。

## 四种完成状态

### 文章稿完成

- `brief.md` 写清材料和边界。
- `sources.md` 可以追溯关键结论。
- `article.md` 事实、标题和语言已复核。

### 图文包完成

- 每张图都有作用、来源和文件。
- 正文图片顺序与 `image-plan.md` 一致。
- 真实产品截图在手机宽度下仍能读。
- 封面为 900×383 左右，并位于正文最后。

### 带图复制版完成

- `带图可复制版.html` 可以离线打开。
- 所有图片已内嵌，不依赖本机路径或临时服务。
- HTML 审计通过，浏览器预览无裂图。
- 复制正文时没有重复 H1、摘要、复制按钮和页面外壳。

### 公众号草稿完成

- 当前文章已出现在指定公众号草稿箱。
- 标题、摘要、作者、正文、图片和封面均属于当前文章。
- 手机预览若未做，必须明确写成未完成，不能用本地预览代替。

## 不得提前宣布完成

- 长现实稿缺少足够材料或关键来源。
- 图片计划标为完成，但文件不存在或没有写进正文。
- HTML 仍含本地路径、临时服务地址、旧稿指纹或图片数量不符。
- 用户要草稿，但后台没有实际保存成功。
- 只有官方演示，却把文章写成作者已经亲测。
